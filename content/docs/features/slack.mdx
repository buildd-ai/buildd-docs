# Slack Integration

Connect Buildd to your Slack workspace to create tasks directly from conversations. Use the `/buildd` slash command to kick off planning tasks without leaving Slack.

## Setup

### 1. Create a Slack App

Go to [api.slack.com/apps](https://api.slack.com/apps) and create a new app for your workspace.

Required scopes:
- `commands` — for the `/buildd` slash command
- `chat:write` — for sending notifications back to channels

### 2. Configure the Slash Command

In your Slack app settings, add a slash command:

- **Command**: `/buildd`
- **Request URL**: `https://buildd.dev/api/integrations/slack`
- **Description**: Create a Buildd task

### 3. Connect in Buildd

There is **no dashboard UI for this**. Configure it through the workspace
integration endpoint, which is **session-authenticated only** — an API key will
not work:

```bash
curl -X PATCH https://buildd.dev/api/workspaces/{workspace-id}/integrations/slack \
  -H "Content-Type: application/json" \
  -d '{
    "teamId": "<your-slack-team-id>",
    "channelId": "<default-notification-channel-id>",
    "botToken": "xoxb-...",
    "enabled": true
  }'
```

| Field | Description |
|-------|-------------|
| `teamId` | Your Slack workspace/team ID — how an incoming command finds this workspace |
| `channelId` | Where notifications are posted. Unrelated to where `/buildd` was typed |
| `botToken` | Bot user OAuth token (`xoxb-...`) |
| `enabled` | Whether the integration is active |

`GET` on the same endpoint returns the config with `botToken` replaced by a
`hasBotToken` boolean.

<Callout type="warn">
Notifications no-op silently unless **all three** of `enabled`, `botToken` and
`channelId` are set. A half-configured integration looks identical to a working
one — nothing warns you.
</Callout>

## Usage

### Creating Tasks

Type `/buildd` followed by a goal in any Slack channel:

```
/buildd research AI agent frameworks and summarize findings
```

This creates a **planning-mode** task in the workspace linked to your Slack team ID. The task includes context about who created it and from which Slack workspace.

You'll receive an ephemeral confirmation message with the task details.

### Adding Context After Creation

Add clarifications through the dashboard or by patching the task — not in Slack.

<Callout type="warn">
Thread replies are **not** captured. The endpoint can match a threaded message
back to a task by a thread timestamp stored in task context, but the `/buildd`
handler never stores one, so no Slack-created task can be matched. Replying in
the thread does nothing.
</Callout>

## Security

Buildd verifies every incoming request using Slack's signing secret:

- Validates the `x-slack-signature` header using HMAC-SHA256 over
  `v0:{timestamp}:{body}`
- Requires `x-slack-request-timestamp` and rejects anything older than 5 minutes,
  to prevent replay
- Rejects requests that fail verification with `401 Unauthorized`

Set the `SLACK_SIGNING_SECRET` environment variable to your Slack app's signing
secret. Slack's initial `url_verification` challenge is answered before the
signature gate, so it succeeds during setup.

## Notifications

Buildd posts back to `channelId` when a worker reaches `completed` or `failed`.
Routine transitions are suppressed — a healthy heartbeat, an automatic retry, and
a budget-reset resume do not notify.

Notifications are fire-and-forget: a Slack API failure is logged and never blocks
task execution.
